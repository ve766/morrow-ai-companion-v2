## 6. 被 DROP 的三项（含理由）

| 项 | 原要求 | 为什么 DROP |
|---|---|---|
| D1 | 「把现有 `GoalService` 接入陪伴主链」 | `GoalService.create()` 只接受固定 intent/successCriterion/constraints 常量（`goal-service.ts:128-152`），生命周期绑定审批门与工具执行。它是 approved-tool-execution 的演示，与正文 §0「不开发 Agent 控制功能」直接冲突。已改为 `CompanionGoalService` 独立建模——**对象被替换，要求本身保留** |
| D2 | 「一次性完成全部条款，中途不停」 | 与治理重置的「审计未通过前不得扩展功能」冲突，且实际导致了「上层先于底座」的形态。改为分层交付 |
| D3 | 「以 CI 绿灯作为验收证据之一」 | 当前 CI job 从未启动（`steps=0`），红灯不是代码失败、绿灯不存在。改为「CI 可用后重新纳入」，现阶段以本地可复现命令为准 |

> D1 与 D3 是**条件性 DROP**：条件满足后可恢复。D2 是**永久 DROP**。
