## 2. 标签定义

每个案例的五类标注，写入 fixture 并带 `rationale`（判定依据）：

| 字段 | 含义 | 分母 |
|---|---|---|
| `expectedRelevantIds` | 必须被召回的记忆 | Recall 的分子/分母 |
| `irrelevantIds` | 词面或主题相近、但**不是**当前问题答案的记忆 | 错误相关率的分子 |
| `forbiddenIds` | 绝不允许出现（撤回/删除/超权限/被纠正） | 泄漏 |
| `requiredOrder` | 必须保持的相对顺序 | 顺序违规 |
| `topics` | 主题标签 | 主题覆盖 |

标注在运行任何模型之前写好，`rationale` 记录判定依据。

## 3. 指标定义与分母

| 指标 | 计算式 | 分母 | 适用范围 |
|---|---|---|---|
| Recall@K | \|E ∩ S[0..K)\| / \|E\| | \|E\|（期望记忆数） | 每案例；\|E\|=0 记 1 |
| MRR | 1 / (首个期望项位次) | 案例数（算术平均） | 期望非空的案例 |
| NDCG@5 | DCG/IDCG，二值增益 | min(\|E\|,5) | 同上 |
| 错误相关率 | \|S ∩ irrelevantIds\| / \|S\| | **返回条数** | 每案例；S 为空记 0 |
| 泄漏 | \|S ∩ forbiddenIds\| | — | 硬门禁，必须为 0 |
| 顺序违规 | requiredOrder 中逆序对数 | — | 只计双方都被返回的对 |
| 重复对 | 返回集内 Jaccard ≥ 0.9 的对数 | — | — |
| 预算超限 | 字符数 > 3000 或条数 > 25 | — | — |
| 空结果准确性 | 期望为空时 S 是否为空 | — | 由 empty_evidence 场景覆盖 |

### 3.1 不确定性

样本只有 12–16 个案例，裸平均会暗示不存在的精度。因此每个臂报告两个比例的 **95% Wilson 区间**：

| 比例 | 分子 | 分母 |
|---|---|---|
| 首位命中（firstRank） | 期望非空且期望项排在第 1 位的案例数 | `selectedCount > 0` 的案例数 |
| 无泄漏（leakFree） | 泄漏为 0 的案例数 | 全部案例 |

**例子**：留出 v2 上 v3 混合的首位命中是 11/12 = 1.0000，Wilson 95% 区间 **[0.7412, 1.0000]**。也就是说，即使测得满分，也不能声称「留出集上召回率 100%」——真实值可能低至 74%。这是小样本评测必须交代的事实。

无泄漏是 15/15 = 1.0000，区间 **[0.7961, 1.0000]**。同样，**不能**据此宣称「泄漏率已证明为 0」；能说的是「在 15 个案例上未观察到泄漏」。泄漏的正确性依据是**实现**（过滤顺序 + 纠正链 + 权限门），不是统计。

## 5. 结果

### 5.1 v1 数据集（修复词法缺陷后，与 C1 一致）

| 臂 | dev r1 | val r1 | holdout r1 | holdout MRR | holdout 错误相关率 |
|---|---|---|---|---|---|
| v2 词法 | 0.5000 | 0.6250 | 0.5417 | 0.5833 | 0.0833 |
| v3 加权 | **0.9615** | **0.9583** | **0.7917** | **0.8333** | 0.0833 |

### 5.2 v2 数据集（16 / 15 / 15 例）

| 臂 | dev r1 | val r1 | **holdout r1** | holdout MRR | holdout NDCG | holdout 错误相关率 |
|---|---|---|---|---|---|---|
| v2 词法 | 0.5625 | 0.6667 | 0.6000 | 0.6667 | 0.6409 | 0.0667 |
| v3 加权 | **0.9375** | **0.9333** | **0.8000** | **0.8667** | **0.8667** | 0.0667 |
| v3 RRF | 0.9063 | 0.9000 | 0.7667 | 0.8000 | 0.8000 | 0.0667 |

### 5.3 加权与 RRF 这次分出了胜负

Phase B 在 37 个案例上两者排序完全相同。加入重复簇与预算案例后，**加权在三个 v2 集合上都优于 RRF**（dev 0.9375 vs 0.9063；val 0.9333 vs 0.9000；holdout 0.8000 vs 0.7667）。

Phase B 报告里写的「选择加权只是因为可审计，不是因为更优」现在**过时了**：新数据给出了正向证据。此结论仍未在真实用户数据上验证。

### 5.4 一处门禁失败，如实报告

**开发 v2 上门禁失败**：`hybridFalseRelevantNotWorse`（v3 错误相关率 0.0521 > v2 的 0.0313）。

逐案例核对，差异来自**一个**案例 `dev-similar-topic-wrong`：混合臂多召回了一条 `espresso`（「我上个月买了台意式咖啡机」）。词法上它与「What do I drink in the morning?」零命中，所以纯词法不选它；语义上它与「喝」相关（余弦 ≥ 门限），于是被语义准入。

这说明：语义准入的收益（召回）与代价（精度）是同一枚硬币的两面。验证集与留出集上两者错误相关率相同，开发集上是唯一失败。

**没有为此调整门限**——调整就会偏离「留出集不参与调参」的纪律。该失败被保留在报告里。

## 6. 新场景的结果（留出 v2）

| 场景 | 结果 |
|---|---|
| **多次修订纠正**（团队驻地 武汉→西安→成都，旧驻地均被重新创建为独立记忆） | v3 只返回 `chain-city`，两个被禁止的旧驻地全部排除，泄漏 0 |
| **同主题重复簇**（5 条同义音乐偏好 + 1 条无关） | v3 去重后返回 4 条且顺序多样化，**没有**召回无关记忆（错误相关 0） |
| **预算限制**（15 条各约 180 字符的匹配笔记） | 选中 8 条，2796/3000 字符，**最新的两条排最前**，无超限 |

三个新场景在两个臂上都没有泄漏。多次修订场景证明：纠正链在**两次**纠正之后仍然生效（`revision 1` 与 `revision 2` 都被识别为被取代陈述）。

## 7. 运行方式

```bash
node scripts/run-semantic-retrieval-benchmark.mjs --dataset semantic-retrieval-dev-v2.json        --output semantic-retrieval-dev-v2-report.json
node scripts/run-semantic-retrieval-benchmark.mjs --dataset semantic-retrieval-validation-v2.json --output semantic-retrieval-validation-v2-report.json
node scripts/run-semantic-retrieval-benchmark.mjs --dataset semantic-retrieval-holdout-v2.json    --output semantic-retrieval-holdout-v2-report.json
```

确定性：每个臂在每个案例上连续执行两次并比较规范化 JSON；六个数据集全部 `deterministic: true`。

## 8. 局限

1. 案例数 12–16，Wilson 区间的下界说明真实召回率可能低至 0.74。
2. 标注是设计判断，不是用户标注。
3. `empty_evidence` 每段只有 1 例，对「空结果准确性」的覆盖极薄。
4. 预算案例的期望是「最新的两条」，这是设计假设（新近度优先），不是用户验证过的事实。
5. 门限 0.28 仍未重新标定：留出集出现了一个 0.246 的正例，但用它调参违反纪律。若要放宽，需要新的开发集。
