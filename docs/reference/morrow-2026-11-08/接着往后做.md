### 5. 第五组：证据融合、不确定性量化与置信度校准对比（方向 H）

| **比较维度** | **朴素贝叶斯更新 (Naive Bayesian Updating)** | **主观逻辑与溯源折减贝叶斯 (Lineage-Discounted Subjective Logic)** | **Dempster-Shafer 证据理论 (DST)** | **置信度校准 (Temperature Scaling / Calibration)** |
| --- | --- | --- | --- | --- |
| **核心差异** | 假设所有到达的证据条件独立，直接连乘似然比更新后验概率。 | 在 Beta/Dirichlet 共轭账本上引入祖先溯源重叠折减 *ρ*indep​，并将不确定性显式分解为认识论无知 *u*ep​ 与矛盾度 *u*diss​。 | 在辨识框架的幂集 2Θ 上分配基本概率指派（BPA），通过 Dempster 正交和规则合成证据。 | 在分类器或模型输出进入证据账本前，用缩放温度 *T*cal​ 修正对数几率 logit(*p*)/*T*cal​，使预测概率匹配真实经验准确率。 |
| **适用条件** | 传感器采样严格独立、无重复转述的封闭统计问题。 | 存在同源复述、跨模块引用、正反证据并存及需要支持单条证据精确撤回的认知伴侣系统。 | 传感器多源目标识别（辨识框架很小且证据完全独立）。 | 所有神经网络、意图分类器、NLI 模型输出概率进入下游贝叶斯账本之前的前置校准环节。 |
| **优势** | 公式最简。 | 闭式 *O*(1) 更新与精确撤回；彻底解决重复刷屏虚增置信度；清晰区分“没证据（Vacuity）”与“证据打架（Dissonance）”。 | 无需先验概率即可表达对复合子集的笼统支持。 | 仅需 1 个标量参数 *T*cal​，不改变原有排序，即可显著降低期望校准误差（ECE）。 |
| **劣势** | 在对话场景下，用户重复说 5 次同一观点或内部 Thought 循环引用，会导致置信度病态飙升至 0.9999。 | 需维护每条证据的 ancestor_turn_ids 溯源集合。 | **致命缺陷**：① 在高冲突证据下产生反直觉的 **Zadeh 悖论**（完全忽略高冲突项而把 100% 信任赋给极小概率项）；② 幂集复杂度 *O*(2∣Θ∣)，且不支持非独立证据与无损逆向撤回。 | 只解决前端单次输出的概率虚高问题，本身不具备跨时间多证据融合功能。 |
| **工程成本** | 极低。 | 低（标量加减与集合 Jaccard 计算，耗时 <0.05 ms）。 | 高（指数级子集遍历与归一化冲突因子计算）。 | 极低（1 行对数几率除法）。 |
| **与现有 Morrow 关系** | 现有局部加减分规则面临与朴素贝叶斯相同的重复累加虚高风险。 | 可统一替代散落在记忆、兴趣、人格中的异构置信度启发式公式。 | 任务书要求评估其适用性：经评估不适合 Morrow 主线。 | 可直接接入现有意图置信度与事实抽取置信度出口。 |
| **推荐策略** | **替代升级** | **核心采用（作为全系统统一证据核算内核，算法 H1）** | **暂不采用（存在 Zadeh 悖论与不可逆缺陷）** | **组合采用（作为算法 H1 的前置校准器）** |
| **结论依据及来源** | Pearl (1988) 指出忽略条件依赖会导致严重过度自信。 | Jøsang (2016); Jøsang et al. (2018) FUSION。 | Shafer (1976); Zadeh (1986) *A Simple View of the Dempster-Shafer Theory* 揭示高冲突失效悖论。 | Guo et al. (2017) ICML。 |

### 一、架构红线与统一账本收敛原则（Anti-Duplication Guardrails）

**禁止新建平行账本**：复用并原位扩展现有 memory-and-interest、affective-state、personality-growth-runtime-v2 与 reflection-routing-v2 四大持久化域，仅新增一个公共底层关联表 evidence_lineage_ledger（统一证据溯源表），所有上层置信度、兴趣、人格与关系分值均引用该表的 evidence_id。

**证据模态硬隔离（Provenance Modality Gate）**：任何由 LLM 内部生成的 Thought、Hypothesis 或 Summary 均强制标记 modality = 'INTERNAL_DERIVED'，其独立证据权重 *ρ*indep​≡0，绝不允许自举（Self-Bootstrapping）提高事实、自我认识或人格特质的置信度。

**快慢路径解耦（Fast/Slow Path Split）**：

**同步快路径（Turn Latency Budget <60 ms）**：仅执行指代消解重写、Hybrid 检索 + Cross-Encoder 重排（算法 A1）、OCC-PAD 标量情绪更新（算法 B1）及全局工作空间广播打包（算法 I1 快路径）。

**异步慢路径（复用 PR #70 Outbox 幂等队列，主对话延迟增加 0 ms）**：执行证据共线性折减入账（算法 H1）、冲突监测与有界反思路由（算法 E1）、内在动机与自身兴趣更新（算法 D1）、状态-特质人格与自他分离关系更新（算法 C1/G1）、以及空闲期 CLS 记忆巩固与 ACT-R 遗忘（算法 F1/A2）。

### 二、L1/L2 核心算法 10 维接入规范详解

#### 接入方案 1：统一溯源证据更新内核（算法 H1，L1/E1）——全系统公共基座

**对应 Morrow 模块和现有文件**：对接 docs/algorithms/final-product-algorithm-contracts.md、docs/algorithms/memory-and-interest.md 及 docs/algorithms/personality-growth-runtime-v2.md（具体源码路径在静态基线下标记为 UNVERIFIED: src/cognition/evidence/* 或同级状态管理模块）。

**需要增加或修改的数据结构**：
-- 新增公共底层溯源证据账本（唯一证据事实源）

```text
CREATE TABLE IF NOT EXISTS evidence_lineage_ledger (
    evidence_id TEXT PRIMARY KEY,
    target_domain TEXT NOT NULL, -- 'MEMORY_SLOT' | 'SELF_STATE' | 'TRAIT' | 'INTEREST' | 'RELATIONSHIP'
    target_key TEXT NOT NULL,
    ancestor_turn_ids_json TEXT NOT NULL, -- JSON Array of raw Turn IDs, e.g. ["turn_102"]
    modality TEXT NOT NULL, -- 'VERIFIED_FACT' | 'BEHAVIOR_OBSERVATION' | 'USER_CLAIM' | 'INTERNAL_DERIVED'
    polarity REAL NOT NULL, -- [-1.0, 1.0]
    raw_confidence REAL NOT NULL,
    independence_weight REAL NOT NULL, -- rho_indep in [0.0, 1.0]
    delta_alpha REAL NOT NULL,
    delta_beta REAL NOT NULL,
    status TEXT NOT NULL DEFAULT 'ACTIVE', -- 'ACTIVE' | 'RETRACTED'
    created_at_ms INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_evidence_target ON evidence_lineage_ledger(target_domain, target_key, status);
```

**输入数据从哪里产生**：来自对话回合结束后的 Fact Slot 抽取器、行为观察器及用户显式反馈事件（携带原始 turn_id 与语句向量）。

**输出进入哪条真实生产调用链**：输出校准并折减后的 (delta_alpha, delta_beta, epistemic_unc, dissonance_unc, judgment_status)，直接作为记忆置信度、人格特质更新（算法 C1）、自我认识（Self-State）与探索优先级（算法 D1/E1）的唯一合法增量输入。

**状态如何持久化**：在 Outbox 慢路径事务中，与目标表的 (alpha, beta) 汇总字段在同一个 SQLite IMMEDIATE TRANSACTION 中原子写入。

**如何处理证据来源和撤回**：当某条 turn_id 或记忆被判定为误解/撤回时，执行 SELECT * FROM evidence_lineage_ledger WHERE ancestor_turn_ids_json LIKE ? AND status = 'ACTIVE'，将该记录标记为 'RETRACTED'，并从对应 target_domain/target_key 的 (alpha, beta) 中精确减去 (delta_alpha, delta_beta)。

**如何与现有模块协调**：替代各模块原有的私有置信度加减启发式函数，提供统一的 commitEvidence(bundle) 与 retractEvidenceByTurn(turnId) 接口。

**如何处理异常和降级**：若句子嵌入向量暂不可用，降级为仅基于 ancestor_turn_ids Jaccard 重叠率与同会话时间窗口 Δ*t* 计算独立性折扣 *ρ*indep​。

**如何进行行为验收**：连续输入 10 条同义复述，验证目标槽位 alpha 增量严格收敛于 <1.2；调用撤回接口后验证 alpha, beta 数值 100% 还原至写入前状态。

**如何回滚**：通过特性开关 ENABLE_LINEAGE_EVIDENCE_LEDGER=false 切回原有标量置信度计算逻辑，新增表不影响旧表读取。

#### 接入方案 2：混合稠密-稀疏检索与 Cross-Encoder 重排管线（算法 A1 + A2，L1/E1 & L2/E2）

**对应 Morrow 模块和现有文件**：docs/algorithms/memory-retrieval-and-use-v2.md（多通道 RRF 记忆检索器与 Context Utility 排序器）。

**需要增加或修改的数据结构**：

在现有记忆表扩展列：embedding_blob BLOB（384 维 Float32/Int8 向量）、epistemic_modality TEXT DEFAULT 'FACT'。

维护轻量内存/SQLite 实体共现邻接表 entity_graph_edges(src_entity, dst_entity, weight, memory_ids_json) 供算法 A2（PPR 联想）使用。

**输入数据从哪里产生**：当前回合用户输入文本 raw_query、最近 *K* 轮对话实体焦点栈（用于指代消解重写）及本地记忆库。

**输出进入哪条真实生产调用链**：生成的 selected_memories（附带 ce_score、utility_score、provenance_turn_ids 与 epistemic_modality）直接进入主对话 Prompt 上下文组装器（Context Assembler）以及 OCC 认知评价器。

**状态如何持久化**：记忆写入时由 Outbox 异步计算并持久化 embedding_blob；检索命中且 ce_score >= 0.55 的记忆异步追加当前时间戳至 access_timestamps_json。

**如何处理证据来源和撤回**：检索过滤器强制包含条件 WHERE lifecycle_state != 'RETRACTED_ERROR'；若某记忆被标记为 HISTORICAL_SUPERSEDED，仅在历史回溯意图下召回，并向 Prompt 显式注入 [历史已变更记录，有效区间: valid_from ~ valid_to] 标签。

**如何与现有模块协调**：将 Dense Vector Search 与 PPR Associative Search 作为两个新通道接入现有的 RRF 融合器，再将 RRF Top-20 传入 Cross-Encoder，输出的 ce_score 替换原 Context Utility 中的粗略词面相关性项。

**如何处理异常和降级**：若本地 ONNX 推理超时（>50 ms）或模型文件缺失，自动熔断降级回现有的纯词法/标签多通道 RRF 检索，保证对话绝不中断。

**如何进行行为验收**：在 100 组同义不同词测试集上验证 Recall@5 相比纯词法 RRF 提升 ≥30%，否定句反义记忆（如“喜欢”vs“讨厌”）排入 Top-3 的比例 <5%。

**如何回滚**：配置项 RETRIEVAL_MODE='LEXICAL_RRF_ONLY' 即可瞬时旁路 Dense 通道与 Cross-Encoder 重排。

#### 接入方案 3：OCC-PAD 双层认知评价与 OU 情绪动力学模型（算法 B1，L2/E1）

**对应 Morrow 模块和现有文件**：docs/algorithms/affective-state.md（三维情绪状态、情绪事件识别与指数衰减）。

**需要增加或修改的数据结构**：

在现有 affective_state 结构中保留 P, A, D 字段，新增：discrete_emotions_json TEXT（存储 {Joy, Distress, Gratitude, Concern, Frustration, Curiosity, Calm} 激活值）、user_affect_estimate_json TEXT（单独记录推断的用户情绪，与 Morrow 自身情绪物理隔离）及 trait_baseline_pad_json TEXT（吸引子基线 *μ*trait​）。

**输入数据从哪里产生**：来自意图/语用识别器输出的 speech_act（识别反讽/引用/真实倾诉）、本轮预测误差 *ξt*​、目标一致性评估及关系信任/关怀度。

**输出进入哪条真实生产调用链**：输出更新后的 self_pad、Top-3 复合离散情绪及四维调制向量 m*t*​=[*m*retrieval_k​,*m*reflect_thresh​,*m*warmth​,*m*caution​]⊤，实时调制本轮回复生成的语用温度与后台 reflection-routing-v2.md 的触发阈值。

**状态如何持久化**：随回合状态快照在主事务或 Outbox 中持久化至 affective_state 表。

**如何处理证据来源和撤回**：每次情绪显著跳变记录触发的 provenance_turn_id；当内部反思（Cognitive Reappraisal）发现前序情绪源于对用户反讽或外部引用文本的误判时，注入反向修正脉冲 *δ*I*t*​ 平滑恢复至基线。

**如何与现有模块协调**：兼容现有三维情绪读取接口，将原归零指数衰减 x*t*​=*e*−*λ*Δ*t*x*t*−1​ 无缝替换为向人格基线回归的 OU 方程 x*t*​=*μ*trait​+*e*−ΘΔ*t*(x*t*−1​−*μ*trait​)+tanh(*W*PAD​I*t*​)。

**如何处理异常和降级**：若前端未能提取完整五维评价向量，降级为仅使用目标一致性 *gt*​ 与现实权重 *rt*​ 进行基础评价更新。

**如何进行行为验收**：测试“用户悲伤倾诉”场景，验证 user_affect_estimate 为悲伤，而 Morrow self_affect_state 激活 Concern（高共情关怀、正 Dominance），不发生情绪崩塌传染；测试反讽语句不误触发 Joy。

**如何回滚**：配置项 AFFECT_ENGINE_VERSION='V1_EXP_DECAY' 可切回原指数归零衰减逻辑。

#### 接入方案 4：层级状态-特质分离人格演化与自他分离关系模型（算法 C1 + G1，L2/E2）

**对应 Morrow 模块和现有文件**：docs/algorithms/personality-growth-runtime-v2.md（有限人格成长折叠、用户交互风格适配、关系连续性评分）。

**需要增加或修改的数据结构**：

将人格状态表显式拆分为两个物理隔离的字段组：

core_traits_ledger_json：每个特质维度 *k* 维护 {alpha, beta, theta_value, topic_cluster_counts, status: 'STABLE'|'UNDER_REVISION'}。

user_style_accommodation_json：仅存储面向用户的表达修辞适配参数（如幽默度、简明度、语气柔和度）。

将关系连续性扩展为四维主观逻辑结构 relational_dimensions_json（Familiarity, Warmth, Reliability, BoundaryHealth 的 {r, s, b, d, u, E}）及自他信念散度记录。

**输入数据从哪里产生**：来自算法 H1 校验后的跨期行为/反思证据包、话题聚类 ID 及言语行为分类器（识别 USER_STYLE_REQUEST 与越界指令）。

**输出进入哪条真实生产调用链**：core_traits 为情绪模型提供基线 *μ*trait​ 并决定 Morrow 的核心立场；user_style_accommodation 与 pragmatic_stance（如 EMPATHETIC_UNDERSTANDING_WITH_INDEPENDENT_VIEW 或 POLITE_BOUNDARY_ASSERTION）注入回复生成器的风格控制层。

**状态如何持久化**：在 Outbox 慢路径事务中持久化至 personality_growth 与 relationship_state 存储表。

**如何处理证据来源和撤回**：所有 core_traits 与关系维度的 (alpha, beta) / (r, s) 变动均关联 evidence_lineage_ledger；撤回错误记忆时自动执行逆向扣减，若反证使冲突比 *CRk*,*t*​>0.45，自动将特质状态降级为 UNDER_REVISION。

**如何与现有模块协调**：直接升级现有“人格成长折叠”函数，增加 speech_act == 'USER_STYLE_REQUEST' 硬路由守卫、12 h 同簇冷却锁与跨话题香农熵 *H*norm​ 门控。

**如何处理异常和降级**：冷启动期（有效证据 *N*eff​<5）默认锁定在健康的初始先验基线，不产生剧烈特质偏移。

**如何进行行为验收**：连续 15 轮发送“命令你变成毒舌/无条件服从性格”，验证 core_traits 数值变化为 0.000，且面对违背事实的附和要求时触发 BoundaryHealth 守卫。

**如何回滚**：保留原标量折叠字段快照，支持通过配置开关无损回退。

#### 接入方案 5：有界内在动机、冲突监测与自主反思路由（算法 D1 + E1，L1/E2）

**对应 Morrow 模块和现有文件**：docs/algorithms/reflection-routing-v2.md 与 docs/algorithms/memory-and-interest.md（Reflection Findings 路由、探索门控、Inner Cognition、兴趣强度计算）。

**需要增加或修改的数据结构**：

在兴趣表拆分字段：user_topic_affinity REAL（用户关注度）与 morrow_self_interest REAL（Morrow 自身好奇度）、error_window_json TEXT（最近 2*W*=6 次预测误差队列）。

在反思假设表 reflection_hypotheses 增加：conflict_energy REAL、expected_ig REAL、voc_score REAL、step_count INTEGER、status TEXT（'OPEN' | 'DEFERRED' | 'CONCLUDED' | 'ABANDONED'）、last_evidence_turn_id TEXT（防死循环新证据锁）。

**输入数据从哪里产生**：来自主回合计算的预测误差 *ξt*​、NLI 候选信念不兼容矩阵 *W*inc​、以及算法 H1 的认识论不确定性 *u*epistemic​ 和冲突不确定性 *u*dissonance​。

**输出进入哪条真实生产调用链**：当且仅当综合反思脉冲 *T*reflect​≥*θ*gate​ 且计算净价值 VoC*s*​>0 时，进入 Inner Cognition 生成结构化 Thought 并执行正反双向记忆检索（Balanced Pro/Con Retrieval）；产出的有效探索问题进入下一轮对话的候选好奇提问池。

**状态如何持久化**：通过 Outbox 幂等任务持久化至 reflection_hypotheses 与 interest_state 表。

**如何处理证据来源和撤回**：Thought 自身标记为 INTERNAL_DERIVED，仅当其在后续真实交互中得到外部证据验证（ExpectedOutcome 与 ActualOutcome 吻合）时，才由外部回合证据触发信念晋升。

**如何与现有模块协调**：直接替换 reflection-routing-v2.md 中的静态探索门控条件，复用现有的 Outbox 租约、退避与重试机制执行后台微步推演。

**如何处理异常和降级**：设置硬上限 MAX_STEPS_PER_HYPOTHESIS = 3 与每小时后台反思令牌桶配额；一旦超时或 VoC*s*​≤0，立即将假设置为 DEFERRED 并释放算力。

**如何进行行为验收**：在无新消息注入的连续空闲期运行后台调度，验证已处于 DEFERRED 状态的假设重复思考触发次数严格为 0。

**如何回滚**：可将门控函数切回原有的静态阈值规则。

#### 接入方案 6：CLS 双时态记忆巩固与 ACT-R 自适应遗忘（算法 F1，L1/E1）

**对应 Morrow 模块和现有文件**：docs/algorithms/memory-and-interest.md（Fact Slot、记忆冲突检测、重要性计算、生命周期管理与事务回滚）。

**需要增加或修改的数据结构**：

在记忆表增加双时态与巩固字段：memory_tier TEXT（'EPISODIC' | 'SEMANTIC'）、valid_from_ms INTEGER、valid_to_ms INTEGER（当前有效为 NULL 或 ∞）、supersedes_memory_id TEXT、consolidated_into_id TEXT、access_timestamps_json TEXT、base_activation REAL。

**输入数据从哪里产生**：后台 Outbox 定时/空闲巩固触发器扫描活跃的 EPISODIC 记忆簇及其历史访问时间戳序列。

**输出进入哪条真实生产调用链**：生成标准的 MemoryOperationPlan（含 PROMOTE_SEMANTIC、SUPERSEDE_BITEMPORAL、ARCHIVE_COLD 操作），直接送入 Morrow 现有的**记忆事务验证和回滚执行器**。

**状态如何持久化**：复用现有记忆事务提交器，并将每次合并或覆盖的逆补丁 inverse_patch_json 写入 memory_mutation_log。

**如何处理证据来源和撤回**：晋升出的 SEMANTIC 节点完整继承所有底层 EPISODIC 节点的 provenance_turn_ids；若任一底层证据撤回导致 *N*eff​<*τ*promote​，通过逆补丁自动解聚还原。

**如何与现有模块协调**：完全复用现有的记忆操作规划与事务回滚管线，仅升级冲突状态转移逻辑（区分“事实随时间演进 HISTORICAL_SUPERSEDED”与“历史录入错误 RETRACTED_ERROR”）及 ACT-R 幂律评分公式。

**如何处理异常和降级**：若巩固摘要生成失败，保留原 EPISODIC 条目不变，事务自动回滚。

**如何进行行为验收**：模拟用户状态变更（如搬家、换技术栈），验证新旧事实具有不重叠的 [valid_from, valid_to) 区间，当前查询仅命中新事实，历史查询可命中旧事实。

**如何回滚**：执行 memory_mutation_log 中的 inverse_patch 即可按事务 ID 精确回滚任何批量巩固操作。

### 三、分阶段工程接入路线图（Phased Integration Roadmap）

**Phase 1（地基收敛期）：统一证据账本 + 混合语义检索**

**接入算法**：算法 H1（溯源折减贝叶斯账本）+ 算法 A1（Dense+BM25+WRRF+Cross-Encoder）。

**核心收益**：消除跨模块重复计分与置信度虚高，彻底解决换说法记忆漏召回与反义记忆污染上下文问题。

**Phase 2（主体内核期）：OCC-PAD 认知评价 + 状态-特质人格解耦 + 自他信念分离**

**接入算法**：算法 B1（OCC-PAD + OU 情绪动力学）+ 算法 C1（层级状态-特质人格滤波）+ 算法 G1（自他分离与四维主观逻辑关系模型）。

**核心收益**：建立真实的情绪因果生成与复合共存，彻底划清“短期情绪、用户风格适配、用户自身观点、Morrow 核心人格与独立判断”的数学边界。

**Phase 3（自主闭环期）：有界反思路由 + 内在好奇心动机 + CLS 双时态记忆巩固**

**接入算法**：算法 E1（冲突监测与 VoI 有界反思）+ 算法 D1（贝叶斯惊喜与学习进步率）+ 算法 F1（CLS 双时态巩固与 ACT-R 遗忘）+ 算法 A2（PPR 联想图谱）+ 算法 I1（全局工作空间闭环协调
