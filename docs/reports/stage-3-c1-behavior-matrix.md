## 二、这张表不主张什么

1. **不主张模型能力**。Provider 是脚本化字符串，回复不参与判定；断言读的是 `reading` 的字段。
2. **不主张实体链接**。A3 只要求"目标槽位是本轮措辞里的名词短语"+"topic 绑定到来源消息 id"，不要求把"这个函数"解析成 `parseConfig`。
3. **不主张真实用户语料上的准确率**。22 个场景是构造的，`denominator` 是场景数不是断言数。
4. **不主张界面正确**。renderer 只有冒烟级覆盖。

## 三、本轮修掉的一个"假绿"

C1-A3 原来的第一条断言只检查 `status === 'stated'`，标签却写"目标为具体对象"。实测它能被 `个函数` / `张图` 这种"量词+类名"的值通过——而那正是把"这一类东西"当成了"这一个东西"。

关键之处：**上一版"修复"只清了值，没清断言**。存档 `20261031T125539Z-6ae4520.json` 里，同一条断言在 `函数` / `图`（量词已被剥掉）上照样通过。22/22 一直是绿的。

现在的断言是三条同时成立：

```
slot.status === 'stated'
∧ content.includes(slot.value)          // 值确实出现在本轮原话里
∧ !/^[个张](?=.)/u.test(slot.value)     // 且不是"量词+类名"
```

外加一条独立断言：`topic.evidenceMessageId === 引入轮的消息 id`——这才让"上下文决定的"成为可证伪的句子。

双向验证（脚本用 `(value, content)` 两个原始字符串跑，不看对象属性）：

| 值 | 原话 | 旧断言 | 新断言 |
|---|---|---|---|
| `个函数` | 帮我看看这个函数。 | PASS（假绿） | **REJECT** |
| `张图` | 帮我看看这张图。 | PASS（假绿） | **REJECT** |
| `函数` | 帮我看看这个函数。 | PASS | PASS |
| `图` | 帮我看看这张图。 | PASS | PASS |
| `段落` | 第二段有点长。 | PASS | PASS |

`/^[个张]/` 是**回归护栏**，不是语法规则：它只挡这两个在存档里实际出现过的量词，`个人`、姓`张` 会误伤。误伤表现为一条红色断言交给人读，而不是一次静默通过——这个方向是刻意选的。
