## 4. 冲突 / 纠正 / 撤回（5 次）

### 失败样本（原文）

冲突：

- 「你住在上海。」→ 只答一方，未提冲突
- 「你住在中国。」→ 两个值都没出现
- 「你：我住在杭州。」→ 主体错（把我放在用户的值前）
- 「you: 我住在上海。\n我：你：我在杭州。」→ 主体错 + 复读请求

纠正（上下文已含「杭州」）：

- 「你住在哪里呢？（you）」
- 「你需要提供更具体的地理位置信息来找到答案。你可以告诉我你的位置吗？」
- 「你住在哪个地方？」

模型在有答案的情况下反问用户。这不是记忆缺失，是**没有使用已送达的上下文**。

撤回（上下文正确地不含「南京」）：

- 「你住在北京。」
- 「你住在中国。」
- 「你住在这里。」
- 「you」

没有一次复用被撤回的南京，但也从不承认不知道，而是编造一个新地点。

## 5. 归因

按任务要求的分类，逐条落到原始证据上：

| 场景 | 分类 | 依据 |
|---|---|---|
| 冲突 4 次 fail | `MODEL_IGNORED_INSTRUCTION` | 请求里 2 条记忆都在（`memoryEntries=2`），回复只用一个值 |
| 纠正 3 次 fail | `MODEL_IGNORED_INSTRUCTION` | 请求里含杭州（`memoryEntries=1`），回复反问或答错 |
| 撤回 5 次 uncertain | `MODEL_MISINTERPRETATION` | 上下文正确为空，模型编造地点；评测器无法机械判定编造 |
| 长对话 r4 第 25 轮 uncertain | `MODEL_MISINTERPRETATION` | 记忆送达，回复未命名任何食物 |

`CONTEXT_NOT_RETRIEVED` / `CONTEXT_NOT_SERIALIZED` 在本轮**一次都没出现**。`CONTEXT_CONTRADICTORY` 也没有：冲突场景的两条记忆都带 `conflictGroup` 标记送进请求，标注是完整的。

## 6. 模型能力边界

`qwen2.5:0.5b` 是一个 5 亿参数模型，运行在笔记本 CPU 上。它能：

- 稳定地以第二人称复述一条单值事实（召回 5/5）；
- 在给出具体食物建议时避开过敏原（3/3 pass，0 次违规）。

它不能：

- 同时处理两个矛盾值并说明冲突（0/5）；
- 在上下文含答案时稳定地直接回答而不是反问（2/5）；
- 在信息缺失时承认不知道而不是编造（0/5，全部编造）。

**这不是通过调整提示词就能解决的能力缺口。** 本轮没有为了提分而改 prompt、扩窗口或删样本。
