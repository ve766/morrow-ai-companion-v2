### 3.1 事实

`evaluation/reports/real-provider-conversation-report.json` 这一个路径被 **5 次 `status: verified` 的运行**依次覆盖。五次都真实，都已从 git 历史恢复：

| 5 | `20261026T155509Z-4aee35` | `c3a000b` | 15:55:09Z | 「我会忘记你在这里的状态。」 | 否 |

### 3.2 逐条排除

| 任务书列出的可能 | 结论 | 依据 |
|---|---|---|
| PR 描述引用了另一轮实验 | **是**（第 1 次） | PR 的 turn-2 `1882` / turn-3 `2149` / turn-4 `1923` 字节与第 1 次运行完全吻合 |
| JSON 对应不同运行/模型/代码 | 同一模型 `qwen2.5:0.5b`，不同运行 | 五次 `provider.model` 一致，`generatedAt` 与请求字节均不同 |
| 报告生成拼接过不同轮次 | **否** | 每份报告内部自洽：`turns` 与 `observations` 来自同一次运行 |
| 判定只查投递、未查使用 | **部分是**，但不是本次矛盾成因 | 投递类检查确实只证明「请求里有」，`observations` 另记模型是否提及；矛盾出在引用了哪次运行，不在判定口径 |
| 原始响应被后处理/截断 | **否** | `responseText` 即为解析出的正文；5 份恢复文件与各自提交 `cmp` 一致 |
| 结果被覆盖 / 复用旧报告 / 引用错文件 | **是，主因** | 固定文件名 + 无运行 ID + 文档只引路径 |

### 3.3 根因

```
固定输出名 → 第 2..5 次运行静默覆盖 → 文档引用的内容被销毁，路径仍存在 → 读者看到相反结论
```

三个条件缺一不可：写入允许覆盖、证据里没有运行 ID、文档只能引用路径。修复同时针对三点（§6）。

### 3.4 未做与不做

- **没有**修改任何 `responseText`、`observations` 或 `checks`。
- **没有**删除任何一次运行；5 次全部保留，且逐字节校验。
- **没有**把第 1 次的成功说成稳定能力——恰好相反，PR 描述已改为「2/5」。

## 10. 是否建议进入下一阶段

**建议先做一件事再决定：在固定采样参数下，把 `b7`/`b5`/`c4` 三个用例重复 5 次。**

理由：本轮最有价值的发现不是任何单个数字，而是**「一次通过」和「一次失败」都不足以支撑结论**——`a3`/`b3` 在同一模型上翻转，turn-4 在同一天 3 次里有 1 次否认自己有过住址。在采样不受控的情况下继续加用例，只会积累更多不可解释的观察。

具体建议顺序：

1. 给评测专用请求加固定 `temperature`（与生产请求分离），重跑 12 项 5 次，得到每个用例的分布而不是单点。
2. 用同一分布重测 `b7`（冲突）与 `b5`（过期）。若 `b7` 在 5 次里稳定只答一个城市，那它是确定的行为缺陷，可以进入产品修复。
3. 修 `b7` 只能靠系统级冲突标记（schema 变更），这属于阶段 4 的输入，不是本轮范围。

**不建议**此时进入 Agent 操控或新功能：模型是否使用上下文这一层还没稳定到可以做基线。
