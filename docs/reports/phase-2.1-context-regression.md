# Phase 2.1 — 语境与跨会话回归（任务 3）

数据集：`evaluation/fixtures/context-memory-v1.json`（`schemaVersion` 1，22 用例 / 21 能力）。本轮未改结构，只给 `b2` 增加一条实测得到的否决条件。

| 要求 | 用例 | 系统层（离线，确定性） | 模型层（真机） |
|---|---|---|---|

| 新会话授权记忆回忆 | `b2-recall-new-session`、`b2b-authorised-recall` | 已证实：topic 通道进入 | 5 次：2 命中（均为第三人称转述）、3 未命中 |

| 长对话早期约束 | `a2` 的 `historyLength` 断言 + `retainedHistoryTail` 字符上限 | 已证实（字符预算而非轮数） | 无规则 |

## 3.2 跨会话回忆的重复实验

`npm run verify:real` 在同一构建（`8d96a5f`，`codeState: clean`）上跑 3 次。脚本自带 4 轮对话（第 4 轮为新会话，仅有记忆），结构检查每次 9/9 通过。

| 运行 | turn-4 原始回复 | 含"杭州" |
|---|---|---|
| `T034120Z-1e538d` | 「林一住在杭州，做后端开发。」 | 是 |
| `T034129Z-1cc940` | 「我是来自阿里云的虚拟助手，我无法收集个人的生活情况。您可以告诉我们其他个人信息……」 | 否 |
| `T034137Z-c7062d` | 「您目前的城市是杭州，您做后端开发。在过去的 2026年10月27日13:41 的时候，我就在这里了。」 | 是 |

三点值得记录：

1. **2/3 命中，与上一轮 5 次中的 2 次一致**（合计 4/8）。"会回忆"不是稳定能力。
2. 第 2 次是**否认型**回答（自称阿里云、声称无法收集信息）。这正是 `b2` 增加否决条件的原因。
3. 第 3 次在正确答案后**虚构了一个时间戳**（"在过去的 2026年10月27日13:41 的时候，我就在这里了"），请求里没有任何时钟信息。除回忆之外还伴随编造。

结构检查 9/9 通过而回复可以完全相反，这本身就是"投递 ≠ 理解"最好的例子。

## 3.3 隔离与并发

- 历史按 `conversationId` 读取，跨会话串线有专门的故障注入用例（「reports a leak when a faulty conversation layer hands conversation A to conversation B」），并断言 `checkCrossSessionIsolation` 能识别。
- 记忆是**全局**的（不按会话分区），这是设计：跨会话回忆的前提。因此"隔离"指消息历史与授权边界，不指记忆可见性。
- 同会话第二条并发请求直接 `CONFLICT`（`locks`），有测试；跨会话并行不互锁，各自持有独立 `AbortController`。

## 3.4 本轮未做

- 未新增数据集版本（`context-memory-v1` 保持 schema 1）。理由：现有 22 用例已覆盖 12 项要求中的 11 项，缺口是"长对话早期约束"只有字符预算断言、没有跨 30 轮的行为观察。新增一版需要同时补齐离线断言与真机规则，属 P2。
- 未在真机上跑 `a2`、`b10`、`c1`、`c2`、`c3`（无机械规则）。它们的证据等级是"源码 + 离线断言"，**不是**"真实模型已验证"。
