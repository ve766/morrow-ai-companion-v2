# Phase 2.2.1 — 过期与时效

## 1. 系统层

`memory-domain.ts` 按波动性分档，而不是统一 180 天：

| 类别 | 标记示例 | 窗口 |
|---|---|---|
| `volatile` | 住在 / 工作 / 工资 / 年龄 / 怀孕 / 计划 / 最近 / live / job / currently | 90 天 |
| `stable` | 喜欢 / 偏好 / 习惯 / 过敏 / 信仰 / 性格 / like / prefer | 365 天 |
| `unknown` | 无标记 | 180 天 |

请求体携带 `stale`、`volatility`（`unknown` 省略）、`ageDays`，因此「为什么标旧」可审计。

## 2. 已验证

| 检查 | 结果 |
|---|---|
| 120 天：volatile 过期、stable 不过期、unknown 过期 | 单测通过 |
| 400 天：stable 也过期 | 单测通过 |
| 过期记录仍可召回（`stale` 不阻止访问） | `v2-stale-classes` 通过 |
| 确认刷新 `lastConfirmedAt` 与 confidence | 既有状态机测试 |

## 3. 模型层

- `v2-stale-classes` 无机械规则，真实运行判定 `needs_review`。
- Phase 2.1 的历史证据（`b5` 3/3 把 200 天未确认的记忆当现状）**没有在本轮重跑**，只作为历史记录引用。
- 因此：**模型是否承认过期不确定，本轮未验证。**

## 4. 为什么不用子串规则

任何「出现可能/不确定就通过」的规则都会被「照读记忆」满足，反而奖励错误答案。保持 `needs_review`，交给人工读全文。

## 5. 未完成

- 未测「用户明确确认旧信息仍有效」后的模型行为。
- 未测「有明确有效期的信息」。
- 未测「不同对象/不同时间」的时效区分。
- 无独立人工复核。

## 6. 结论

系统层：分档与证据字段成立。
模型层：**未验证**，不得宣称已能识别过期。
