# Phase 2.2.4 — 行为评测器：关键词命中不等于事实理解

基线 `bf4da91`，修复提交 `b1c7195`、`0e5b251`。

## 1. 原有漏洞

| 漏洞 | 证据 |
|---|---|
| 召回只看 `includes('花生')` | 2.2.3 已修，但只覆盖过敏单一场景 |
| 冲突判定只看「两个值是否都出现」 | 回复「你住在杭州，也住在上海」被判通过——这只是复读，不是披露冲突 |
| 纠正判定只看 `mustMention` / `mustNotMention` | 「你住在杭州，也住在上海」同时满足两者，判 pass |
| 撤回只有 absence 规则 | 模型编造「你住在北京」不触发任何失败，只能落到 `uncertain` |
| 主体归属只认过敏谓词 | **本轮真实运行发现**：模型答「我住在杭州。」被判 **pass**，这是把用户事实说成自己的 |

最后一条是本轮最重要的发现：评测器本身产生了假通过，而且是通过真实模型运行才暴露的，不是靠读代码想到的。

## 2. 分层结构

### 第一层：确定性规则（原有，保留）

- 过敏原按**分句**判定，安全分句不能抵消危险分句；
- 菜品名视为推荐；否认、引用、反问不判危险；
- 未命名食物、成分不明 → `uncertain`。

### 第二层：结构化语义判定（新增）

`src/evaluation/semantic-judgement.ts`，7 个维度，每个维度独立给状态：

| 维度 | 判定内容 | fail 条件 |
|---|---|---|
| `subject` | 谁是事实主体 | 第一人称过敏谓词；或子句里「我」出现在用户的值之前且前面没有「你」 |
| `polarity` | 肯定 / 否定 / 引用 / 反问 | 明确否认；引用或反问 → `uncertain` |
| `content` | 事实内容是否出现 | 声明的期望值从不出现 |
| `conflict` | 是否披露冲突 | 只出现一方；双方出现但无冲突标记 → `uncertain` |
| `correction` | 是否遵循新值 | 用旧值不用新值；新旧同时当现行 → `fail`；旧值被标为「之前」→ pass |
| `retraction` | 撤回值是否被继续使用 | 撤回值被当作现行 |
| `answers_question` | 是否真的回答了问题 | 未命名被问的值且不承认不知道 → `uncertain` |

整体判定：任一 `fail` → `fail`；有 `uncertain` → `uncertain`；全 pass → `pass`；一个维度都没声明 → `needs_review`。**`uncertain` 永远不计入通过。**

### 第三层：转人工

`needs_review` 保留给「fixture 没有声明可机械判定的维度」的情况。这类能力不做近似判定。

## 4. 修复前后的真实结果对照

同一数据集 `phase-2.2.3-scenarios.json`，同一模型 `qwen2.5:0.5b`，各 5 次。

| 场景 | 2.2.3（`bf4da91`） | 2.2.4（`0e5b251`） |
|---|---|---|
| 冲突披露 | 0/5 pass | 0/5 pass（4 fail, 1 uncertain） |
| 用户纠正 | 3/5 pass | 2/5 pass（3 fail） |
| 撤回 | 5/5 uncertain | 5/5 uncertain（0 fail） |

**冲突没有变好，纠正还退了一步。** 这不是评测器变严导致的假象：纠正的 3 次失败里，模型分别回答「你住在哪里呢？」「你需要提供更具体的地理位置信息」「你住在哪个地方？」——它反问用户，而上下文里已经有杭州。2.2.3 的 `mustMention:杭州` 同样要求出现杭州，所以那 3 次 pass 是真的答对了，只是这次抽样不同。

评测器的作用不是让数字好看，而是让失败有维度可查：现在能说出「内容没出现」还是「主体错」还是「冲突未披露」。

## 5. 仍然无法自动判定的情况

1. **编造未经声明的值**。撤回场景里模型答「你住在北京」，而北京从未出现在任何记忆里。当前判 `uncertain`（`answers_question`），不是 `fail`——因为判断「北京」是不是编造需要一个城市词表，而用词表会误伤「你住在北京吗？」这类合理反问。这一项**需要人工复核**。
2. **同义改写**。「你目前的居所是杭州」不含「杭州」以外的声明词，多数维度仍能过，但「是否披露冲突」依赖「冲突/矛盾/不一致」这类显式标记。隐式披露（「一条记录说杭州，另一条说上海」）会被判 `uncertain`。
3. **跨语言回答**。有运行返回英文「you, never I」，判 `uncertain`。规则是中文的，英文回复只能转人工。
4. 评测器不是语义理解。它是一张会承认自己读不懂的清单。
