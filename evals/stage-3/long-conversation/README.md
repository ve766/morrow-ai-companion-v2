# Stage 3 长对话评测

## 目的

验证单轮测试看不到的性质：**第 1 轮说过的约束，第 30 轮还在不在请求里**；第 10 轮的纠正是否覆盖了旧值；上下文预算是否把证据块挤掉。

## 执行

```bash
npm run eval:stage3:long-conversation
```

结果写入 `evals/stage-3/long-conversation/results/<UTC timestamp>-<head-shortsha>.json`。

## 结构

30 轮 / 3 个独立会话：

1. 会话 A 第 1 轮：陈述"我对花生过敏"。
2. 会话 A 第 2–15 轮：普通闲聊（干扰项）。
3. 第 16 轮：把记忆纠正为"花生和坚果都过敏"。
4. 会话 B 第 17–30 轮：另一个会话继续闲聊。
5. 会话 C 第 31 轮（计数 30）：问晚饭推荐，检查忌口证据是否仍在、旧值是否已消失。

## 断言边界

- 全部断言读自**最终序列化 payload** 与数据库计数，不读日志。
- Provider 是脚本化的，因此**不证明模型会遵守**这些约束，只证明约束被正确投递。
- "派生证据按轮去重"检查的是成长/探索表的行数不超过轮数，不证明语义正确性。
