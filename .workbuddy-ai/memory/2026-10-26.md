# 2026-10-26

## Morrow V2.1 Phase A/B：检索算法升级

仓库 `ve766/morrow-ai-companion-v2`，分支 `feature/algorithm-v2-phase-a`（基线 `8b207b7`，HEAD `6455f9d`）。Draft PR: https://github.com/ve766/morrow-ai-companion-v2/pull/1

### 做了什么

- 基线审计 `docs/algorithm-v2/phase-a-baseline.md`（结论：检索词法主导、来源不参与排序、无跨记录纠正链、检索不可重放、M3 评测器与生产脱耦、CI 在 main 上红）。
- 新增 `src/memory/retrieval/`：config / trace / lexical / context-format / supersession / v2 / strategy / registry。
- v1（`MemoryContextAssembler`）保留为对照臂，排序算术未改；新增 v2 多信号算法，已切换为默认。
- 新增生产算法对照基准：`npm run evaluate:retrieval`，12 例合成 fixture，指标 Recall@1/3/5、MRR、NDCG@5、泄漏、顺序违规、重复对、主题覆盖、预算超限、确定性。
- 闭环证据：`src/app/retrieval-request-context.integration.test.ts` 断言实际下发的 HTTP 请求体。

### 关键结论

- v1 泄漏 1（纠正掉的旧陈述复活）、顺序违规 1、重复对 6；v2 全为 0，MRR 0.9167→0.9583，NDCG@5 0.9385→0.9692，无指标退化。
- 纠正链实现方式：`listSupersededStatements()` 读 `memory_revisions`，**无需新增迁移**（schema 仍 15）。
- 无新增迁移、无新增网络调用。

### 环境/工具限制（下次别再踩）

- 该仓库 `npm ci` 用 `--ignore-scripts`，本地跑测试前必须先 `node node_modules/electron/install.js`，否则 5 个 import `electron` 的 suite 会因 "Electron failed to install correctly" 失败。
- 本机 `npm run smoke` 会失败：GPU 进程崩溃 → `renderer-load-failed`。属环境阻塞，CI 的 windows job 才是权威。
- GitHub token **缺少 `workflow` 作用域**，无法推送 `.github/workflows/*` 变更。需要改 CI 时必须先换凭据，不要试图绕过。

### 已知未解决

无语义检索（必须共享词项）；纠正链只识别完全相同的文本；稳定性分类是关键词启发式；基准仅 12 例无统计意义；M3 评测器仍未与生产打通；Linux Electron smoke 仍红。

## Morrow Phase B：混合检索与语义召回

分支 `feature/algorithm-v2-phase-a`，起点 `2b6373b`，HEAD `8c2fa5e`。Draft PR #1。

### 做了什么

- 复核 Phase A：发现并修复两个缺陷 —— 检索未使用回合固定时刻（可致 CONFLICT）、纠正链窗口静默截断 200 条（改为 2000 + `correctionChain.truncated`）。确认 Phase A 的 v2 指标是在被报告的同一批案例上调参得到的。
- 三段独立评测集（dev 13 / validation 12 / holdout 12），11 类语义场景。
- 候选方案对照：v2 词法 / v3 归一化加权 / v3 RRF。留出集 recall@1 0.4583→0.7917，MRR 0.5417→0.8333，错误相关率 0.125→0.0833，泄漏 0。
- 实现 `memory-retrieval-v3-hybrid`：语义信号走同步端口，纠正链在打分之前，语义只进 relevance 不进置信度。
- 闭环：6 个真实模型用例断言实际下发的 HTTP body。

### 关键结论

- 语义召回只修好 11 个场景中的 5 个，2 个仍失败（间接表达、一个跨语言方向）。
- dev/validation 的 MRR 1.0 是乐观偏差，holdout 0.83 才是可信值。
- 加权与 RRF 在 37 个案例上排序完全相同 —— 融合方式没有实验依据分出胜负。
- 代价：模型 130MB、RSS +500MB、冷启动 2.1s。**未写入生产依赖**，打包后的应用不会加载模型。
- Electron 主进程内 ONNX 可用（`dim=384`），无需 rebuild。

### 环境/工具限制（重要）

- 本机 `ELECTRON_RUN_AS_NODE=1`，会让 electron 退化为 Node，`require('electron')` 返回路径字符串。跑 Electron 探针要 `env -u ELECTRON_RUN_AS_NODE`。
- GitHub token 仍缺 `workflow` 作用域，CI 文件改不了；`evaluate:retrieval` 仍未进 CI。
- 本机 smoke 因 GPU 崩溃失败，CI 才权威。
- `@huggingface/transformers` 用 `npm install --no-save` 安装，`npm ci` 会清掉它 —— 语义评测前需重装。
