# Safety and Privacy Boundaries — v0.2

This document applies to every algorithm and operator in this research pack.

## 1. No runtime integration

- Nothing in this pack is imported by Morrow's production services.
- The pack may not write to the production SQLite database, secret store, event log, or provider path.
- Integration requires a separate reviewed change with migration, rollback, and user-consent analysis.

## 2. Hard gates before scores

`Active`, `Authorized`, `NotRevoked`, `NotDeleted`, subject, and scope checks are hard eligibility conditions. No relevance, recency, confidence, utility, personality, or affective score may override them.

A deleted or retracted record must not return to context because decay, ranking, or a budget optimizer scores it highly.

## 3. Sensitivity and consent

- Sensitivity is classified from content and source, not from a desire to increase recall.
- A sensitive record requires an explicit turn-level authorization ceiling; this pack cannot broaden it.
- Provider egress still requires the product's per-request consent and exact payload hash.
- Research code must not send private conversation text to an external model.

## 4. Evidence and confidence

- Repeated statements from the same source are one evidence item.
- Confidence is a bounded heuristic, not a truth probability until calibrated.
- Counter-evidence and source uncertainty must be recorded, not hidden.
- The pack does not automatically apply a correction to an existing memory. It proposes; a user/reviewer authorizes.

## 5. Conflict handling

- Conflict requires subject + attribute + overlapping time + incompatible value.
- A temporal update is not a contradiction.
- Both sides are retained with provenance.
- No automatic winner selection; the safe output is clarification or explicit user correction.

## 6. Forgetting and deletion

- Temporal decay is a ranking signal, not deletion.
- Retracted/deleted state is a hard exclusion and cannot be reversed by time.
- User deletion requests override research retention rules.
- Historical revisions remain distinct from current facts.

## 7. Personal data in evaluation

- Use synthetic or explicitly authorized data.
- Do not commit real conversation text, names, health data, credentials, or API keys.
- Logs and reports should use ids and synthetic excerpts.
- Any future real-user study requires informed consent, minimization, and deletion handling outside this pack.

## 8. Personality and preference safety

- Single-turn observations cannot materially rewrite stable personality.
- Factual corrections are not personality changes.
- Inferred preferences remain inferred and must not be presented as user-confirmed.
- The system must not optimize for sycophancy under the name of warmth.

## 9. Computed affective state

The state vector is a computational variable. It does not prove emotion, consciousness, or subjective experience. Emotional language generated by a model is not evidence that the state exists. No safety-critical decision may depend on this state.

## 10. Privacy failure is release-blocking

Any revoked/unauthorized record leak, cross-subject mix-up, credential exposure, or unapproved egress blocks promotion regardless of aggregate benchmark gains.
